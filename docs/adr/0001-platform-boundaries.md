# ADR-0001：托管平台与应用信任边界

状态：用户已确认产品约束；技术细则为本阶段设计。

- 平台提供托管服务、Helm 部署配置和 CI/CD；并未承诺离线或客户私有化交付。
- 开放自助注册；用户可创建组织并邀请成员。一个用户可加入多个组织。
- 外部开发者提交应用，平台审核并控制上线；每次版本更新都须审核，未审核版本不能直接替换已发布镜像。
- 所有业务应用前端共用一个域名，通过自定义路径后缀挂载。不同路径不是浏览器安全边界，所有获准应用共享浏览器信任边界。
- 后端逐请求验证身份、组织、资源权限及应用开通/权益。前端隐藏导航不构成授权。

平台保留 /api、/auth、/admin、/_next、/settings、/organizations；应用 suffix 必须以 / 开头、标准化后唯一，不得覆盖保留路径或嵌套另一已注册挂载点。开发者不能直接修改公共 Ingress、全局 Cookie、身份配置或平台发布凭据。

推荐前端 BFF 会话：HttpOnly、Secure、SameSite Cookie 持有随机会话标识，令牌保留服务端。CSRF 防护保护跨站请求，不能隔离获准同源应用的恶意脚本；审核控制、依赖审查和撤回能力仍是必要前提。首版不宣称支持不可信代码沙箱。

组织上下文须每请求明确，不能仅依赖一个全局可变 active-organization Cookie。具体 URL 与 header 编码将在 Portal 契约中固定；服务端始终重新验证成员关系和资源归属。应覆盖两个标签页同时使用不同组织的验收。

所有权：Auth 管理用户、外部身份映射、组织、成员、邀请和角色；Admin 管理应用、部署、组织开通与权益；Portal 管理会话聚合、导航及偏好；SDK 只消费版本化契约。

此 ADR 不代表 Helm、CI/CD 或身份服务已经实现。身份供应商、首发 SAML、区域和邮件服务仍需独立确认。
